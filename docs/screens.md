# 화면 설계

`GET /...` 엔드포인트 목록(정적 파일)을 바탕으로 화면을 정한다.
사용자는 한 명, 만든 사람 본인이다 (`CLAUDE.md`).

## 1. 플로우 3개

1. **뉴스 + 이어지는 흐름** — 사용자가 / 오늘 새로 나온 반도체 뉴스를 훑어보고 과거에 이어지는 사건이 있으면 같이 보려고 / 뉴스(오늘) → (같은 화면 안에서) 카드의 "이어지는 흐름 N건" 펼치기 → 원문(외부, 화면 아님)
2. **모르는 용어 찾기** — 사용자가 / 기사에 나온 낯선 용어(예: HBM4)의 뜻을 확인하려고 / 뉴스(아무 날짜) → 카드 안 용어 링크 클릭 → 개념(해당 항목으로 앵커 이동)
3. **회사 몰아보기 → 못 찾으면 검색** — 사용자가 / 특정 회사(예: 인텔)가 최근 어떤 뉴스에 나왔는지 몰아보려고, 안 보이면 옛날 기사를 검색해서 찾으려고 / 뉴스(아무 화면, 상단 탭) → 기업 목록(분류별) → 기업 프로필(그 회사 기사 최신순) → (거기 없으면) 검색 → 검색 결과에서 원문(외부)

## 2. 필요한 화면 목록

플로우 3개에서 나온 화면은 5개다.

1. 뉴스 (오늘 / 날짜별)
2. 개념
3. 기업 목록
4. 기업 프로필
5. 검색

`/ui/*.html`(UI 후보 목업), `/slices/*.md`(개발 명세)는 어느 플로우에도 안 나온다 — 아래 A 참고.

## 3. 화면 표

| 화면 이름 | 사용자가 하는 일 | 부르는 엔드포인트 | 빈 상태 | 에러 상태 |
| --- | --- | --- | --- | --- |
| 뉴스 (오늘/날짜별) | 그날 기사 카드를 훑어보고, 카테고리 칩으로 거르고, 카드 안 "이어지는 흐름"을 펼쳐 과거 관련 기사를 본다 | `GET /`(최신일) · `GET /{YYYY-MM-DD}.html` | 그날 기사 0건 → "이 날은 반도체 관련 기사가 없습니다. (수집은 정상이었습니다)" 고정 문구 | 전용 에러 화면 없음. 일부 피드 실패는 메타 줄에 "수집 N곳 중 M곳 정상"으로만 숫자가 뜬다 — **기사 0건이 실제로는 수집 실패 때문이어도 본문엔 "수집은 정상이었습니다"라고 고정으로 뜬다** (`CLAUDE.md` "실패는 실패라고 적는다"와 어긋나는 지점) |
| 개념 | 등재 용어 18개의 정의·출처를 훑어보거나, 기사에서 클릭해 특정 용어로 바로 이동한다 | `GET /concepts.html` | 등재 용어 0개 → "등재된 개념이 없습니다." (지금은 18개라 실제로 안 뜸) | 없음 |
| 기업 목록 | 분류별(8개)로 묶인 회사와 회사별 기사 수를 훑어본다 | `GET /companies.html` | 그 분류에 회사 0곳 → "아직 등재된 회사가 없습니다." (분류 단위로 뜬다) | 없음 |
| 기업 프로필 | 회사 설명을 읽고, 그 회사가 나온 기사를 최신순으로 본다 | `GET /company/{slug}.html` | 설명 미확인 → "설명은 아직 출처를 확인하지 못했습니다." / 그 회사 기사 0건 → "아직 이 회사가 나온 기사가 없습니다." | 존재하지 않는 slug → Vercel 기본 404 (전용 화면 없음) |
| 검색 | 검색어를 입력해 화면에 실제로 뜬 적 있는 기사(254건, 누적) 중 제목·요약이 일치하는 것을 찾는다 | `GET /search.html` (화면) → 안에서 `GET /search-index.json` fetch | 검색어 없음 → "전체 N건에서 찾습니다." / 검색어는 있으나 일치 0건 → "일치하는 기사가 없습니다." | **`search-index.json` fetch 실패 시 처리가 없다** — `.catch()`가 없어 "색인을 불러오는 중…" 문구에 멈춘 채 사용자에게 실패를 알리지 않는다 |

## A. 어느 화면에도 안 붙는 엔드포인트

- `GET /ui/{a-newspaper,b-cards,c-timeline,d-merged,concepts}.html` — 세션 초반 UI 후보 목업 5개. 지금 화면 어디서도 안 걸린다
- `GET /slices/{01~08}-*.md` — 개발 명세 원문 8개. 개발자(나) 참고용이지 사용자 화면이 아니다

배포에서 지워야 할 것은 아니다(정적 산출물이라 배포에서 빼려면 `render.py`/빌드 과정을 손대야 함) — 다만 "화면"으로 설계하지 않는다는 뜻.

## B. 화면에 필요한데 엔드포인트가 없는 것

- **검색 결과 딥링크** — 검색 화면은 `?q=` 같은 쿼리를 안 읽는다. 검색해서 찾은 결과를 링크로 저장하거나 공유할 방법이 없다(정적 사이트라 서버가 쿼리를 처리할 데가 없음). 플로우 3에서 "찾은 기사로 다시 돌아오고 싶다"가 생기면 이게 막힌다

이 하나만 확실한 gap 이다. 그 외에는 "화면 자체가 없다"가 아니라 위 표의 에러 상태 칸(수집 실패 문구 고정, 검색 fetch 실패 무반응) 쪽 문제로 판단했다 — 화면은 있지만 상태 처리가 비어 있는 경우라 B 가 아니라 위 표에 적었다.
