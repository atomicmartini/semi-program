# 기능: 사용자가 몇 달 전 사건까지 거슬러 올라간 흐름을 볼 수 있다

`WBS.md` 3.2 backfill 의 확장. RSS 가 안 주는 과거분을 **목록 페이지에서** 가져온다.

## PLAN.md·CLAUDE.md 와 달라진 부분

`CLAUDE.md` 스택에 적힌 수집 방식은 **RSS** 다. 이번엔 RSS 가 못 주는 구간이라
**목록 페이지 HTML 을 읽는다.** `fetch.py`(RSS)는 건드리지 않고 `archive.py` 를 따로 둔다.
수집처 주소는 규칙대로 `data/sources.md` 에만 적는다.

**기간을 사용자 답변에서 옮긴 것** — 답은 "6개월 × 월 5건" 이었으나 최근 6개월(2026-02~07)은
**05·06·07 이 이미 있는 달**이라 절반이 중복이 된다. 분량은 그대로 두고 창을 뒤로 밀어
`2025-11 ~ 2026-04` 을 채운다. 기간은 명령행 인자라 나중에 바꾸기 쉽다.

## 완료 조건

- [ ] `python archive.py 2025-11 2026-04` 실행 시 달마다 최대 5건씩 받아 `data/articles/<날짜>.json` 에 합쳐진다
- [ ] 이미 있는 기사(원문 링크가 같은 것)는 다시 넣지 않는다 — 두 번 실행해도 새 기사 0건
- [ ] 받은 건수와 **달별 실제 확보 건수**를 출력한다. 5건을 못 채운 달은 채운 만큼만 적는다

## 안 되는 경우

- 목록 페이지가 403/타임아웃 → 그 사이트만 실패로 적고 **다른 사이트는 계속한다**. 조용히 넘어가지 않는다
- 목록 구조가 바뀌어 한 건도 못 읽음 → "0건 파싱됨" 을 경고로 출력한다 (`CLAUDE.md` — 피드는 조용히 죽는다)
- 요청한 달에 반도체 기사가 5건 미만 → 있는 만큼만. 억지로 채우지 않는다

## 이번에 안 하는 것

- **삼성전자 뉴스룸은 넣지 않는다** — 조사에서 `/page/N`(N≥2) 접근이 4회 모두 연결 실패했다. 유일한 `[공식]` 후보라 아쉽지만, 확인 안 된 것을 넣지 않는다
- **기사별 원문 페이지는 열지 않는다** — 목록 페이지에 제목·요약·날짜가 다 있다. 요청 수를 몇 배로 늘릴 이유가 없다
- **발행 시각(시·분)은 안 가져온다** — 목록 페이지에 날짜만 있다. `published` 는 `T00:00:00` 으로 두고 원문 표기를 `published_raw` 에 남긴다. 화면에 `00:00` 으로 보이는 것은 이번에 안 고친다
- `link.py`·`render.py` 재실행으로 흐름을 다시 잇는 것은 이 슬라이스 끝에 명령으로만 한다. 코드는 안 고친다

## 건드릴 파일

- 새로 만들 파일: `archive.py` · `test_archive.py`
- 고칠 파일: `data/sources.md` (아카이브 경로 절 추가)

## 확인 방법

- `python -m unittest test_archive.py` 통과 (파서·달별 고르기는 저장해 둔 실제 HTML 조각으로 검사, 네트워크 없이)
- `python archive.py 2025-11 2026-04` → 달별 건수 출력
- 다시 한 번 실행 → 새 기사 0건
- `python link.py 2026-08-22` → 이어지는 흐름이 이전보다 늘거나 더 과거로 간다
