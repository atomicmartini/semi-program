# 기능: 사용자가 오늘 뉴스 아래에서 과거 관련 사건을 볼 수 있다

`WBS.md` 7.1 `link.py`. 선행 `3.2 backfill`(완료·67일치) · `6.1 extract.py`(막힘 — 아래 참고).

## PLAN.md 와 달라진 부분

`extract.py` 가 아직 검증 전(모델 429)이라 그 결과물(관계·인용구)을 못 쓴다.
`WBS.md` 4절 "자르는 순서"가 이미 이 상황을 대비해 정해 둔 완화책을 그대로 쓴다 —
**"연결은 기업명 겹침만으로 판정".** 그래서 이 슬라이스는 `extract.py` 를 기다리지 않고
`filter.py`/`pick.py` 가 이미 쓰는 `data/companies.md` 사전만으로 시작한다.

## 완료 조건

- [ ] `python link.py <날짜>` 실행 시, 그날 선별된 기사마다 과거 기사 중 **공통 기업이 있는 기사**를 점수와 함께 출력한다
- [ ] 공통 기업이 하나도 없으면 **"이어지는 흐름 없음"**으로 표시한다 (억지로 잇지 않는다 — `PRD.md` 암묵지)
- [ ] `data/articles/<날짜>.linked.json` 이 생성되고, 기사마다 `related: [{date, title, url, shared_companies}]` 필드가 채워진다

## 안 되는 경우

- 과거 기사가 아예 없는 시점(가장 이른 날짜) → `related: []`, 에러 아님
- 오늘 기사에 `companies.md` 사전 기업명이 하나도 없을 때 → 그 기사만 `related: []`
- 같은 점수의 과거 기사가 여러 건일 때 → 최신순으로 최대 3건까지만

## 이번에 안 하는 것

- `extract.py` 의 관계(`relations`)·인용구는 안 쓴다 (막혀 있음, 위 참고)
- 진짜 "후속"(인과·시간 순서) 판정은 안 한다 — **공통 기업 언급만으로** 잇는다
- 기업명 정규화 시스템을 새로 만들지 않는다 — `companies.md` 사전에 있는 것만 매칭 (`WBS.md` 3절, 범위 밖)
- `render.py` 화면 연결은 아래 "물어볼 것 3" 답에 따라 이 슬라이스에 넣거나 다음으로 뺀다

## 건드릴 파일

- 새로 만들 파일: `link.py`
- 고칠 파일: 없음 (읽기만 — `data/companies.md`, `data/articles/*.json`)

## 확인 방법

- `python link.py 2026-08-22` → 콘솔에 기사별 연결 건수·점수 출력
- `data/articles/2026-08-22.linked.json` 을 열어 최소 1건에 `related` 가 비어 있지 않은지 확인 (67일치 과거 데이터가 있어 가능성 높음)

## 물어볼 것 — 답 받음

1. **임계값** — 공통 기업 **1개**면 잇는다
2. **"과거"의 범위** — **제한 없음.** 67일 전체를 본다
3. **화면 연결은 이번엔 안 한다.** `linked.json` 까지만 만들고 `render.py` 연결은 다음 슬라이스
